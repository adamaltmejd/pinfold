# Pinfold 0.4.0

Linux image builds now use isolated, finite BuildKit jobs on Firecracker instead of Podman's host image store. A separate converter prepares completed roots; launching a completed image does not require the builder.

## Caller changes

- **Breaking Linux migration:** Podman-only image references no longer resolve. Rebuild profiles with `pinfold build --profile NAME`, projects with `pinfold build`, and caller images with `pinfold image build`. The Podman and `runtime-dir` prerequisites are removed. Existing Podman storage, derived roots and managed agent disks are preserved.
- Linux builds require user-accessible KVM, unprivileged user namespaces, Landlock and e2fsprogs. First use acquires and verifies the pinned builder bootstrap. Keep the installed executable's AppArmor profile loaded on hosts that restrict user namespaces.
- `pinfold build` now accepts `--no-cache`. Profile and project builds reuse layers by default; use this flag to rerun package-update and other RUN steps. Caller `image build --no-cache` remains available.
- Linux `build` and `image build` accept repeatable `--allow HOST` additions to the build allowlist, independently of agent egress. macOS rejects these additions as `build-allow-unsupported`.
- Project and profile configuration can select a local `image`, with project precedence. Profiles may omit their recipe. An explicit image overrides the profile recipe and receives no recipe-freshness claim. An explicit image plus a project `containerfile` refuses as `image-source-conflict`; missing sources and empty images refuse as `image-source-missing` and `image-invalid`. Launch never implicitly pulls, imports or builds. `build` with no selected recipe refuses as `image-no-recipe`.
- Linux image IDs are runnable OCI manifest digests. On both platforms, only managed project builds record the selected local profile identity: caller/profile output has `"base": null` and `dev.pinfold.base=""`. Other consulted identities remain internal. Unique and latest references publish together.
- Linux uses the pinned Dockerfile frontend; `#syntax` cannot replace it. Unsupported inputs and attachments are refused rather than silently substituted.
- Cancellation during running Linux work before catalog commit retains exit 1 and the `cancelled` token; a stop after commit preserves success. Cleanly handled failed jobs can preserve ordinary layer cache while pruning unused mutable RUN cache mounts. Interrupted or unclean cache work is discarded. Concurrent Linux builds sharing the cache can refuse as `builder-in-use`.
- `pinfold config` adds `image_source` (`explicit`, `project`, `profile`); explicit images have `containerfile: null`. On Linux, `image_built` reads the local catalog without runtime access; an absent image reports `false` with `image_error: null`.
- Linux `artifacts` and doctor add a `builder` entry with the archive digest as `version`, asset `bytes`, and `recipe_sha256`. Damaged bootstrap bytes refuse as `builder-integrity`; a changed or missing selected profile dependency refuses as `image-base-changed`.

No other CLI flag removal, box-spec field change or exit-code change is introduced by this release.

## Updated pins

Bun 1.4.4, Claude 2.1.314, Codex 0.166.0, and the public suffix list dated 2026-10-28. Rust and Cargo dependency versions remain unchanged. All changed artifact digests were verified against their publishers.

## Known limits

- The existing caller-label output issue remains open: accepted OCI labels can be absent from CLI image output. The accepted image retains the labels.
- Strict live mounts remain deferred. This release does not claim arbitrary-project or concurrent builder capacity, complete externally observed handoff ordering, or a new latency guarantee.
