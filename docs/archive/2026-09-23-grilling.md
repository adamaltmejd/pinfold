# Spec review, 2026-09-23

A question-by-question review of `docs/ARCHITECTURE.md`. It records what
changed, why, and what was rejected. The spec wins where they differ.

## Terms

A Terms section in ARCHITECTURE.md, not a separate `CONTEXT.md`: the spec
is binding and a glossary beside it would drift. Rationale stays in the
archive, so there is no ADR directory.

## Forwards cut from v1

Nothing in v1 needs one: herdr has no socket in v1, Switchyard workers use
routes. No guarantee tested them, and the box spec had no field for them.
Adding them later costs no more than now, because init and the CLI come from
one build and the socket protocol is private to it. herdr's filtered forward
is a Yard ticket.

## Config

- Only the pi layer reads a profile's `pinfold.toml`. The spec said both
  "egress never comes from a profile" and that the profile's `pinfold.toml`
  is a config layer for `allow`.
- `allow`, `routes` and `protect` are unions across layers. Under plain
  precedence, a project's `allow = ["crates.io"]` would drop the model API.

## Image builds

Trust hashed the Containerfile but not its build context, so the agent
could edit a `COPY`ed script that the next build runs with unrestricted
egress. Project builds now get an empty context, and only `pinfold build`
builds. Rejected: hashing the whole context.

## Project identity

The hash in `projects/<name>-<hash>` is of the canonical root path. A moved
checkout is a new project; `clean` reclaims the old state.

## Commands

- `pinfold run` became `pinfold pi`, which `pi` shims, so "run" is no
  longer both a command and a noun.
- `pinfold shell` became `pinfold attach`, an exec into the running pi box.
  A fresh shell box would have needed its own rule for `.git`. Switchyard
  never used `shell`: gates go through `box up` with their own mounts.

## Git: read-only `.git` replaces the handoff

The threat: host git runs code named in `.git` (hooks, `core.fsmonitor`,
`core.pager`, `commondir`), and shell prompts run `git status` on every
`cd`. The spike showed no partial mount layout protects a writable `.git`.

| Option | Risk | Complexity | Agent commits |
|---|---|---|---|
| A. Per-run git dir, bundle in the box, fetch, automatic fast-forward (the previous spec) | none | high: git dir build, bundle step, fallback box, CAS, index reset, non-fast-forward cases | yes |
| B. As A, but the host copies objects and refs out as plain files and fetches from a clean dir | none | medium | yes |
| C. Host `.git` mounted read-only | none | one mount | no |
| D. Writable `.git`, checked or cleaned after the run | host code execution | medium, grows with git | yes |

Chosen: C for v1. Interactive runs are watched and diffs reviewed on the
host anyway. D is out: a writable host `.git` is all or nothing, so no
"slightly riskier" middle exists.

Also rejected: a host git shim over a socket (add, commit, switch, branch).
Host hooks such as husky and pre-commit run worktree files the box writes;
arguments like `commit -F`, `--template` and `--pathspec-from-file` read
host files that the box can read back; signing would put the user's
signature on agent content; and it needs forwards and a filter.

Kept for later, in a Yard ticket: a single "snapshot commit" operation, a
fixed `git add -A && git commit` with hooks and signing off. It is simpler
than B once forwards exist, so it is to be trialled first, then B.

Worktrees are refused in v1. A worktree's `.git` is a file in the writable
project, host git follows its `gitdir:` line, and Apple `container` cannot
mount a file read-only.

## Editor config

The box can write `.vscode/`, `.claude/` and `.idea/`, which the host runs
when it opens the project. These are now always read-only. The line is
auto-execution: build scripts, tests and package scripts run only by the
user's command and are listed as not protected.

## Init

The init had been a pinned, downloaded artifact, so a dev CLI could run
against a released init. It now always comes from the CLI's own build.

## Profiles

- `pinfold profile new NAME [--from PROFILE]`, so the embedded default can
  be copied and edited.
- Nothing a box can write maps to a profile. A profile reaches every
  project, so a writable one would let one injected box plant an extension
  in all the others.
- Seeds stay copy-if-missing, at start. Rejected:
  - Profile wins at every start: pi writes its global `settings.json`
    itself (`lastChangelogVersion`, `/settings`, Ctrl+S model, `pi install`),
    so every in-session change and every global install would revert.
  - Reseed on build: a rebuild for `apt-get upgrade` would wipe project pi
    config, and seeds live in the project home, not the image.
  To reseed, delete the file from the project home.
- pinfold does not manage pi settings. Rejected for v1: a `pi install`
  redirect in the shim, and an `add-package` command. A project→profile
  command (`profile new --from-project`) is a Yard ticket.

pi facts behind this, from pi 0.86.1: settings are two layers, global
(agent dir) and project (`.pi/`), deep-merged with project winning.
Missing packages auto-install at startup over the network unless
`PI_OFFLINE=1`, which skips them silently. Local-path packages are used in
place. `settings.json` is written in place with `writeFileSync`.

## Default allowlist

The model APIs pi uses for Claude, OpenAI, OpenRouter and OpenCode,
including the OAuth token hosts (`platform.claude.com`, `auth.openai.com`),
plus `registry.npmjs.org`. `PI_OFFLINE` stays unset so a missing package
fails loudly with a 403 rather than silently. The box learns the list from
`PINFOLD_ALLOW`.

## Deferred past v1

Each becomes a Yard ticket once the v1 tickets are filed, not before.

- **herdr forward.** Forwards (a host unix socket at a guest path, relayed
  by init) with a filter that passes only `pane.report_agent` for the box's
  own pane. Needs a box-spec field, a guarantee and its test.
- **Agent commits.** Trial the snapshot-commit operation first: a fixed
  `git add -A && git commit` on the host, hooks and signing off, over a
  filtered forward. Option B above if it falls short.
- **Project to profile.** `pinfold profile new NAME --from-project PATH
  [--force]`: copy a project home's pi config into a profile's `home/`,
  leaving out sessions, `auth.json`, caches and `npm/`. Host-side only. It
  also covers saving a configured pi session as a profile.
- **Worktrees.** The worktree's `.git` file must be unwritable by the box,
  since host git follows it. podman can bind-mount a file read-only; Apple
  `container` needs another way. `GIT_DIR` in the box alone does not help.
