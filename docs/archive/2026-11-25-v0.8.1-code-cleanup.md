# v0.8.1 whole-tree audit, 2026-11-25

v0.8.0's pass (2026-11-25-v0.8.0-code-cleanup.md) read only the modules
changed since v0.7.0, against AGENTS.md's rule of a whole-tree read
before every release. v0.8.0 was already published when that was
caught, so this pass reads the rest of the tree and lands as 0.8.1.
Together the two passes cover every module.

Eleven read-only readers covered `cli` with `main` and `update`; the
Apple runtime; the Firecracker runtime with `sockets`; `clean` with
`image` and `artifacts`; `crossing` with the disks; `ownership`,
`process`, `runs` and the rest of `core`; the guest `init` with `dirs`;
the `pi` layer; the e2e harness; and the test files in two groups. One
builder landed the findings on `cleanup-0.8.1`.

## Landed

Thirteen commits, one per module:

- cli: `exec_admission` inlined; `print_profile`'s width a constant.
- runtime: `exec_command` lost an unused context and its `io::Result`;
  Apple's `native_exec` moved into `Runtime::exec`; three cancel checks
  use `pipe::check_cancel`; `Plan.vsock` is no longer an `Option`; one
  generation-entry list.
- image, clean: `Phase::egress` used everywhere; `prune_boxes` returns
  its list.
- crossing: one nonblocking loop.
- ownership: one `request_stop`; a repeated `set_nonblocking` gone.
- init: one fresh-root ownership helper, one log trim; `relay_builder`
  inlined.
- pi: `cloexec`, `closed` and `succeeds` gone; one ref listing builder;
  two `unsafe` fd conversions are `From` conversions.
- e2e harness: the fixture's accept loop is detached; setup checks use
  `Exec::ok`; `BoxUp::ended` reuses `drain`. A fix: row 26's host
  `base64` ran through a bare `Command::spawn`, outside the harness's
  spawn lock (#379); it now uses `e2e::spawn`.
- Tests: two exact JSON-line assertions in disk controls and a line
  count in sessions, each implied by a kept assertion; Adam's cuts
  below.
- Spec: `apparmor-profile` is listed among the commands without the
  daily pass, matching the code.

## Rejected

- Crossing and export validation that repeats the caller's checks
  (`check_args`, `valid_name`, the no-branches refusal, the 4096-byte
  line check, the object width check, `disk_export`'s name check): kept
  as checks at the Git-only crossing, where core must not rely on pi.
- `init/builder.rs` `send`'s re-stat and size check, and the
  `stop_work`/`sync` after the daemon stops: they bound what crosses to
  the host and flush the cache; no measurement says they cost anything.
- `disk_export.rs` raw `libc` calls as nix calls, landed then reverted
  in review: nix 0.32 maps an unknown errno to 0, so an NFS error such
  as 521 would print as `os error 0`. Re-admit when nix keeps the raw
  errno.
- `core/mod.rs` `directory_entries` as `nix::dir::Dir::from_fd`: nix
  0.32 leaks the fd when `fdopendir` fails. Re-admit when nix closes it.
- `ownership.rs` `Claim` holding `StartupControl`: closes a partly read
  stop connection earlier. Re-admit with a guarantee naming that order.
- `init/builder.rs` `Daemon`'s Drop: the only cleanup on a panic in PID
  1. Re-admit if init aborts on panic.
- `init/firecracker.rs` `mount_at` via `make_directories`: adds a
  refusal and drops the symlink error text.
- `cli.rs`/`launch.rs` one Apple "image not found" check: changes a
  lookup failure from `image-missing` to a runtime error.
- `main.rs` one project-verb set: changes the private owner verb's exit
  code. Re-admit with any change to that verb.
- Apple `own_disks` removal via `down`, `wait_ready`'s double tests:
  change kill order or exit timing.
- Image: `verify_root` reuse, one allocated-bytes walker, catalog
  `check_cancel`, the served-config budget charge, the build record's
  `policy`, `program()` (in #467): each changes a check, a size, a JSON
  key or a message.
- Profile `write_profile` via `write_share`: changes copied modes.
- `CommandGuard` traits as free functions: about 20 call sites for 6
  lines.
- pi `Lease.child` reaping: kept; the client can outlive a dead owner.
- Harness `Below::wait_gone` via `wait_exited`: a per-pid deadline.
- Test twins: records.rs's env-literal absence in `inspect` (covers the
  whole record, not only `env`); sessions.rs's same-generation check
  after a client is killed; clean.rs's idle-session helpers (needs
  `stop`'s lock release confirmed first).
