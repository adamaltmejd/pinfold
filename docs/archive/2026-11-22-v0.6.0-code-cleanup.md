# v0.6.0 release audit, 2026-11-22

The code-cleanup pass with test-audit's sweep, then the spec pass, before
the breaking 0.6.0 release. Seventeen read-only readers covered every
source module, the harness, each test file, the spec with `profile/`, the
README with the help text, and the three trace tables (configuration
keys, CLI verbs and flags, guarantee rows). Nothing was edited in that
phase. The findings landed in #410 (spec, README, help, recipes) and #411
(code and tests), each with one Codex review.

## Landed

- Runtime and Apple: the exec transport's unset stop and deadline, the
  EXEC frame's unused working-directory field, repeated `fstatat` and
  path-splitting code in `sockets.rs`, one-caller wrappers.
- Firecracker: one deadline-bounded vsock connect for unmount and the
  cancellable exec; one `kill`; the shared cancellation check.
- Init and config: one hex encoder, one `set_window`, one `stop_work`
  for PID 1 and the builder, bounded-read and log-tail helpers, the bare
  `init receive DIR` form.
- CLI: one box lookup for `stat` and `exec`, the update notice that never
  ran, a second image resolution, and `"base": null` from `image build
  --json` (Adam's decision; a caller change).
- Core: `Inject::check` shared by structure-only validation and
  resolution, the second name-in-use check, login destinations computed
  once, serde defaults for records only this build writes.
- Disk and crossing: the optional cancel that was always set, with
  `own_disks`'s dead no-cancel paths; one-caller helpers.
- Images: one private-directory helper, one canonical index, the
  always-measured build cache, base refresh inside the Apple build, two
  repeated allowlist checks behind the callers' own.
- Proxy and process: `errno` through nix, one repeated cancellation
  check. The spec now names the `write timeout` closure line (Adam's
  decision).
- pi layer: peer uid through nix, one request-target accessor, the
  accept and departure watchers written once, `exchange_rex` folded into
  `exchange`, the optional locator mount and frame defaults.
- Tests: 432 lines removed, 154 added. Twins of another block, checks of
  store layout and file names, and values read back from pinfold's own
  output were deleted. Row 45's existing-destination case is now a
  dangling symlink. Separately, the symlink its successful export copies
  now points at a mode 0600 host file, so a chmod through the link fails
  the test. Nine guarantee rows were reworded to state
  what their tests do. Row 15's Apple clause, which had no test, was cut
  (Adam's decision).
- Spec, README and help (#410): restatement, history and measurements
  cut; the `disk` line added to the CLI block; `pinfold box` and
  `pinfold image` presented as the developer interface (#340); the
  README states `/project`, `PINFOLD_PROJECT`, the push output, host Git
  2.29 and the start and stop status lines.

The review of #411 caught two regressions from the pass. The shared
`Inject::check` echoed a malformed route's `to` on stderr; no route
target is echoed now, including the login route and the plain address
route, which echoed before the pass. The shared `stop_work` polled a
descriptor it never read and dropped poll errors; 8f544c3 reads the
polled descriptor and returns them.

## Rejected, and what would re-admit each

- Proxy upstream dial through nix (-44): too close to a release for the
  proxy's connect path. Ticket #412.
- The guest's host-only vsock peer check: a control. Never as a cleanup.
- `validate_project`'s first validation call, `require_repo`, the
  profile share copy, `Publication`, the two `allocated_bytes`, the
  second vsock handshake, `dial`'s cancellation check: each differs in a
  refusal, a message or a reported number. Re-admit with a proof of
  identical behaviour or as an intended change.
- `make_proxy_connectable` through `output`: the finding was wrong; it
  saved nothing and changed an error.
- bun from npm tarballs, the resolver writing `target`, the checksum
  format check in the agents stage: need a test build of the recipes.
- An additive allow key for profiles: a feature, with #331.
- The relay's one-second drain for a crossing's output: not reproduced
  with a 600 MB fetch.
- Row 38's first-run decision assertions: the second run asserts the
  same contract.

## Proof limits

The Mac suite reuses an existing default image, so it does not build the
recipes: the recipe edits in #410 and the moved agent pins are exercised
by a separate profile build before the release. Thirty-odd CLI flags and
configuration overrides have a spec line and no test (the trace tables
list them); they are not guarantee rows. Open questions are unchanged.
