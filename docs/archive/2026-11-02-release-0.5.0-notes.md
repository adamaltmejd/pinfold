Run Pi outside a Git repository, keep its work on independent disks, and export
files explicitly when you want them on the host.

## Caller changes

- `pinfold pi` outside Git starts in `/work` with fresh, independent home and
  work disks. The invoking folder is neither mounted nor copied. Disks survive
  exit; their reported names work with `disk ls`, `disk export` and `disk rm`.
  Two starts from the same folder do not share disks. Repository sessions keep
  their existing persistence and branch synchronization. Git worktrees remain
  unsupported.
- When no local `.pinfold.toml` exists, configuration falls back to
  `$XDG_CONFIG_HOME/pinfold/pinfold.toml` (normally
  `~/.config/pinfold/pinfold.toml`). An existing local file always wins, even
  when empty. Invalid local files fail instead of falling back. Neither file
  is created implicitly. Local trust checks remain; global configuration is
  host-owned policy. A global `containerfile` is unsupported; select a profile
  instead.
- `pinfold disk export NAME DEST [--image IMAGE]` exports a stopped, clean,
  unattached disk into a new directory. Treat exported files as untrusted.
  Symlinks remain links; existing destinations are never replaced. Export uses
  the local default profile image unless `--image` selects another image, and
  never builds or pulls a missing image automatically. Success prints
  `{"event":"exported","disk":NAME,"destination":DEST}`. Missing or unfilled
  disks refuse with `disk-missing`; unclean disks refuse with `disk-unclean`.
- On Pi exit, bounded summaries report retained work. Repository summaries
  distinguish committed changes available through fetch from uncommitted and
  untracked work. Scratch summaries identify retained disks and the export
  command. These notices do not copy files automatically.
- `pinfold config` JSON adds `mode` (`repository` or `scratch`) and
  `config_source` (the selected path or null). Scratch `project.disks` is null.
  No existing flags or exit codes are removed.

## Bundled agent

Pi is updated from 1.4.0 to 1.5.0. Its default OpenAI model is now
`gpt-6.1-sol` when no model is selected. Pi's tool argument validation now uses
pi-schema: custom extensions using TypeBox features outside JSON Schema need
review; JSON Schema tools gain argument coercion. See the
[upstream notes](https://github.com/earendil-works/pi/releases/tag/v1.5.0).

## Maintenance

Remove duplicate init parsing, connector and directory-creation work. The
release audit changes no test assertion or runtime security control. The slow
response test now has an explicit release gate; the normal CI budget is
unchanged. Nightly pin releases also check bootstrap producer code for
unreleased implementation changes.
