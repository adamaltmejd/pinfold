# v0.5.3

Security and reliability fixes for audit logging and guest isolation.

- Cap each box and Linux image-build audit log at 128 MiB and fail closed.
- Keep unprivileged Firecracker workloads eligible for the guest OOM killer across fork and exec.
- Disable nested user namespaces in Apple guests and verify the limit before readiness.
- Apply no_new_privs to Apple PID 1 and independently started exec workloads.
- Refresh Claude, Codex, Ponytail, TOML and public suffix pins.
- Extend the existing copied-Git-disk proof without another box or build. Keep the existing controls while removing small implementation duplicates and redundant assertions.

## Caller changes

- At the audit cap, boxes stop with `audit-log` (exit 1). Linux image builds fail before publication; an already committed build retains success. Prior complete lines remain intact. Requests already forwarded cannot be recalled.
- Apple workloads requiring nested user namespaces are refused by the guest kernel.
- Unprivileged Firecracker workloads may lower `oom_score_adj` to -999, but cannot obtain score-based immunity through `oom_score_adj` or `oom_adj`. Host VM memory limits stay unchanged.
- **Allowlist compatibility:** the PSL refresh tightens suffix-entry admission, including `.apps.grok.bot` and `.grok.bot`; affected entries fail with `spec`. New rules: `manus.space`, `docsflowy.site`, `linkyhost.page`, `auth.lovable.app`, `pagelemon.dev`, `sanity.run`, `sanity.studio`, `sliplane.app`, `*.apps.grok.bot` and `*.pages.grok.bot`. This admission change does not affect exact-host entries.

No CLI flag, JSON field or exit-code definition is removed.

Doctor and lifecycle investigations were closed as unconfirmed, not fixed. Evidence limits and reopening triggers are retained in the dated disposition note. Draft PR #264's additional retention coverage remains deferred under the unchanged five-minute CI gate; it is not claimed by this release.
