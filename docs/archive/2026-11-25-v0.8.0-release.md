# v0.8.0 release, 2026-11-25

A release cut by hand from main. It carries implementation changes since
v0.7.0 (1c3d25d7), so the nightly pin job would skip it. The audit is in
2026-11-25-v0.8.0-code-cleanup.md.

## Changes since v0.7.0

- #453, #454: each test block names its sabotage; the test policy keeps
  only critical behavior.
- #456: on macOS a project folder in `mounts` may be `kind = "share"`.
  A share folder that contains the project root is refused.
- #462: the `op` key is merged into `from`. A `from` value starting with
  `op://` is a 1Password reference; any other value names a host
  variable.
- #463: a `login = "github"` route gives `gh` and Git in the box GitHub
  access while the token stays at the proxy. #459 added a `basic` header
  option for this, and #463 removed it before any release.
- The cleanup pass, on the release branch. The github login route sets
  Git's `http.postBuffer` for `github.localhost` to 500 MiB, so a push
  over the 1 MiB default is not sent chunked, which the proxy refuses.
  `config edit`'s template shows a github route and no secret in
  `env`.

## Caller changes

- The `op` key is removed, a hard break. An env entry, injecting header
  or login route that names `op` no longer loads. Write
  `from = "op://…"` instead. `config --json` and `doctor --json` report
  a reference under `from`, no longer under `op`.
- A route may be `{ login = "github", from = VAR_OR_REFERENCE }`.
  - It is served as `github.localhost` and `api.github.localhost`. These
    two names, not the route's own, are the `routes` keys in a launch
    record and in `box inspect` under `launch.record`, and the API
    name's `to` carries `/api/v3` when the route sets `to`.
  - The configuration reports (`config --json`, `doctor --json`) show
    the route under its own key, as declared.
  - Either name colliding with another route, including a second github
    login route, refuses a start as `spec`.
  - The box's environment gets `GH_HOST`, placeholder `GH_TOKEN` and
    `GH_ENTERPRISE_TOKEN`, and `GIT_CONFIG_COUNT` with its
    `GIT_CONFIG_KEY_n` and `GIT_CONFIG_VALUE_n` for three entries:
    `url.http://github.localhost/.insteadOf` for `https://github.com/`
    and `git@github.com:`, and
    `http.http://github.localhost/.postBuffer` 524288000. These names
    appear in a launch record's `env`. A caller env entry naming any of
    them refuses as `spec`.
  - The route follows the common login-route rules: guest credential
    headers are replaced, a credential-named query on either name gets
    403 `login credential query`, and an unavailable credential fails
    `box up` with exit 1 and reason `login`.
  - `provider` on a github login route refuses as `spec`.
- On macOS a project's `mounts` folder entry accepts `kind = "share"`;
  Linux refuses it as `spec`. `config --json` `project.folders` and
  `doctor --json` `config.project.folders` can show `kind` `share`, and
  a share folder entry in a launch record's `mounts` is a share mount.
  A share folder containing the project root refuses a start as `spec`.
- Allow entries newly refused by the Public Suffix List: `.airoapp.ai`,
  `.aspirethemes.com`, `.sites.aspirethemes.com`, `.blacktops.app`,
  `.blacktops.page`, `.faable.link`, `.greybull.site`, `.host.cloud`,
  `.ipdisk.co.kr`, `.iptime.org`, `.onhomemade.com`,
  `.shared.atlassian-3p.com`, `.shared.atlassian-3p-us-gov-mod.com`,
  `.shared.atlassian-isolated-3p.com`, `.shipstatic.com`. No longer
  refused: `.adimo.co.uk`, `.diadem.cloud`, `.leapcell.dev`,
  `.leapcell.online`, `.mircloud.host`, `.mircloud.us`.
