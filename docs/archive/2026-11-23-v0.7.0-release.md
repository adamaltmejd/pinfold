# v0.7.0 release, 2026-11-23

A release cut by hand from main. It carries implementation changes since
v0.6.3 (62b5c7a6), so the nightly pin job would skip it. The audit is in
2026-11-23-v0.7.0-code-cleanup.md.

## Changes since v0.6.3

- #436: each bundled profile lives in one directory, `profile/<name>/`.
- #437: a refusal the proxy answers with an HTTP response names its
  logged reason in a `Proxy-Status: pinfold` header. A parsed refusal
  other than `HEAD` also has a text body.
- #438: on macOS, `clean` returns the build cache's pruned blocks to the
  host. The build-cache line in `clean` and `doctor` is reworded.
- #439: Linux no longer rechecks a box's image tag or recorded image
  ID after `box up` has resolved and leased the image. A tag moved
  after that point no longer refuses the start.
- #441: a project can mount further host folders read-only.
- #442: on macOS, `clean` stops the idle builder, and warns when a
  running build keeps it from finishing.
- #443: the pin script moves the Public Suffix List only with
  `--suffix-list`.
- #444: the seeded agent instructions say each fact once. The pi
  extension states the allowed hosts and the 403 rule at every start.
- #445: the spec says a Linux disk's host allocation does not shrink
  when files are deleted in the box (#446 tracks discard).
- #447: `clean --unused AGE` is renamed `clean --idle AGE`.
- #448, #449, #450: the cleanup pass. `clean --dry-run` runs no automatic
  pass. The login helper runs in its own process group. The Linux guest
  no longer repeats host checks on the BOOT request and the builder's
  devices. curl's `--max-time` and `--max-filesize` are gone; pinfold's
  deadline and byte limit bound every transfer.

## Caller changes

- `clean --unused AGE` is removed and exits 1 as an unknown option. Use
  `clean --idle AGE`.
- A project's `mounts` accepts read-only folder entries after the
  project mount.
  - `config --json` gains `project.folders`, and `doctor --json` gains
    `config.project.folders`.
  - Each folder is a `{kind, host, guest}` entry in a launch record's
    `mounts` and in `box inspect` under `launch.record.mounts`.
  - A malformed folder entry refuses a start or a join as `spec`. At
    box start a folder can also refuse as `path-not-utf8` or
    `host-path-in-project`. A join whose valid folder list differs
    from the running box's refuses as `config-changed` naming `mounts`.
- On Linux, when an image tag moves after `box up` has resolved and
  leased the image, `pinfold box up` no longer fails with
  `image-changed`, and `start` and `-- CMD` no longer fail with
  `owner-unavailable`.
- `clean --dry-run` no longer triggers the automatic daily pass.
- `clean` on macOS can print one of two stderr warnings and keep its
  exit status: a running build keeps it from finishing, or the builder
  did not answer.
- Inside a box, a refusal the proxy answers with an HTTP response
  carries `Proxy-Status: pinfold` with an `error` value (`http_request_denied`, `http_request_error`,
  `dns_error`, `proxy_internal_response` or
  `destination_ip_prohibited`) and the reason in `details`.
- `bundled-profiles-changed` prints once at the next eligible launch of
  an installation that recorded the earlier profiles.
- No allow entry is newly refused or no longer refused: the Public
  Suffix List did not move.

## Pins

`scripts/bump-pins.py --suffix-list` moved Firecracker from 1.17.0 to
1.18.0 with guest kernel `guest-kernel-6.18.57-firecracker-v1.18.0`.
bun 1.4.5 and anydoc 0.2.5 are not yet eligible. The Public Suffix List
did not move. `cargo update` locked no new package.
