## Judgment

The recommendation to preserve subprocess ownership is supported. The demonstrated losses divide cleanly between caller-side discarding and binary-owned missing/ambiguous evidence. A public SDK, service, or embedded library is not necessary to repair either. Recommend small consumer repairs followed by separately specified diagnostic guarantees. Do not present the scratch adapter or prototype B as the finished architecture.

## Required report corrections

1. **Do not claim backpressure/cancellation validation from `edge.json`.** The supposedly slow observer had already exited within 200 ms; `cancelled-query` returned 0 and 13,726 bytes. In the source, termination runs only if the process is still alive, so this case never canceled the query or filled the pipe. It supports only: withholding reads at this output size did not block this owner. The consumer's cancellation receipt covers `box list`, not every query or exec operation. A blocked/no-reader guarantee remains unvalidated.

2. **Separate bounded reading from bounded storage and durability.** `inspect-run` bounds source bytes/records per call. Generation log files and snapshots have no retention/count/disk budget. A busy box's egress file still grows. `save()` uses ordinary writes/rename without fsync, exclusive creation, explicit mode, or symlink protection. Records are immutable by program convention, not verified durable/untamperable. A disk exhausted by retained data can also hit the existing fail-closed audit path. Call this a retained-query feasibility prototype, not a production bounded diagnostic store.

3. **Do not claim full applied-control provenance.** Prototype B records resolved allow entries, route names, image ID, runtime kind and requested CPU/memory. It does not record source origins/hashes, runtime versions, mount/protection controls, observed resource enforcement, or startup refusal snapshots. Pi's changed-config experiment demonstrates why historical effective values matter, but not that field-level source provenance has been implemented or tested. Keep requested and observed controls distinct.

4. **Use existing generation as the identity.** The baseline already returns `dev.pinfold.generation` inside labels. Prototype `run_id` is exactly that value. The demonstrated deficiency is name-keyed egress history and inaccessible retained effective facts, not the complete absence of lifetime identity. Recommend first-class exposure/consistent correlation of the existing generation, not a second identity allocation system. Define scope for pre-claim failures separately; do not quietly expand one box generation into a universal attempt/job tracing model.

5. **Scope static checks narrowly and state their limitations.** `passes-static` is appropriate. It does not establish DNS safety, SNI, request framing, upstream connectivity, authentication, or application success. `refused` here is a counterfactual authority decision from recorded facts, not evidence that a request occurred. No request path is evaluated. If historical policies can outlive binary rule changes, define how evaluator version mismatch becomes unavailable or qualified; never silently reinterpret an old snapshot as its original decision.

6. **Treat shared-check extraction as a control change requiring verification.** The patch replaces production proxy checks, not just presentation code. Source order appears preserved for the representative branches, but a few HTTP fixtures/static calls do not establish equivalence for suffix matching, case normalization, malformed ports/authorities, literals, routes and all DNS/SNI/framing interactions. Sharing the narrow predicate avoids a second policy implementation; it does not waive the existing security/e2e gate. Do not describe the prototype as validated enforcement parity.

7. **Do not collapse “allowed” into successful access.** Baseline already distinguishes policy-refused HTTP 403 from route-upstream HTTP 403 using decision/reason/status. Linux's failed route is `decision=allowed,status=null` with client HTTP 502. macOS times out at the five-second curl deadline and has no completed corresponding log row in the sampled history. The latter does not prove the request was denied, never seen, or permanently unlogged. The reproduced gap is a reliable cause/stage and partial-operation observation, not that the existing log is useless or universally misclassifies HTTP 403.

8. **Retained terminal evidence still loses important details.** `edge.json`'s live terminal event contains `reason=exited, detail=exit status: 137`; retained terminal stores only `exited`. Pi stores coarse `pi-ended` even though the end could include different outcomes. `not-observed` also conflates absent, corrupt, unreadable and oversized terminal records. Production reporting should distinguish unavailable from genuinely unobserved and retain safe structured status. SIGKILL plus a ready snapshot proves only earlier readiness and missing terminal observation; the separate `stat` probe establishes the orphan's existence in these cases.

9. **Consumer prototype is not yet a validated typed API.** It retains generic `Record<string,unknown>` JSON, accepts arrays as objects, and does not validate ready identity or event sequence. Its `stop()` returns process-end status without checking a terminal teardown result. Call it a reference adapter demonstrating retention and process handling. Do not describe it as a finished typed outcome/error taxonomy. The observed 200,000-byte exec demonstrates raw separate delivery and 64-KiB retained tail, not arbitrary-output/backpressure safety. Synchronous sink exceptions and blocking are unhandled; raw exec still uses `close` and can wait for descendant-held pipes. These are limitations, not grounds for a new SDK layer.

10. **Keep process exit, stream completion and teardown separate.** The revised owner's one-second post-exit drain deadline is an adapter policy, not a Pinfold guarantee. `outputDrain=deadline` must remain visible and must never be reported as complete output or completed cleanup. The SIGKILL receipt supports this distinction. Do not extrapolate it into guest-command cancellation: terminating a wrapper is not proven to stop its independently grouped runtime child or guest command. Explicit owner shutdown stays separate from observer cancellation.

11. **Exec metadata is justified; its specific transport remains a design choice.** Guest exit 3 and absent-box exit 3 are reproduced. No byte pattern in guest stdout/stderr can safely distinguish them. An opt-in extra FD is a plausible smallest Unix mechanism, but it is not prototyped here. Define terminal management result, generation binding, descriptor ownership, EOF/missing outcome, blocked/closed reader behavior, and raw-stream preservation before adopting it. Do not promise this gap is repaired by richer `up` records or a typed wrapper.

12. **Repair evidence provenance or narrow claims.** `prepare.py` wrote HEAD/branch/status/file hashes into `evidence/baseline.json`; the runtime probe then overwrote that filename. `working-tree.patch` survives, but it is `git diff` and the scratch copy copies tracked files only. Unless another source manifest was preserved or the copied baseline is independently reconstructed/matched, do not claim a preserved complete source-hash manifest. Record baseline/prototype binary hashes, source revision plus dirty delta, runtime versions, exact commands and intervention differences. `no-runtime-inspect` sets PATH to a nonexistent directory: this demonstrates no executable lookup dependency for that successful query, not a probe of a hung service. The first Linux environment refusal is a setup failure, not a diagnostic regression. Baseline and prototype timings are illustrative single runs, not performance estimates.

## Minimal ordering

First repair existing caller information loss and classify raw outcomes honestly. Then specify generation-correlated applied facts and retained query availability/retention semantics in the binary; this is a new guarantee with privacy and disk consequences. Add the narrow static explanation only if historical facts plus actual decision events do not answer the workflow sufficiently; it is lower priority than preserving a known failure cause. Keep any reference TypeScript implementation near its actual consumer. Keep the Rust controller on direct subprocesses until measured repeated integration work establishes an SDK need. Resolve the reproduced owner closed-stdout cleanup fault independently before increasing the owner protocol's output volume.

## Scope of endorsement

The receipts support the architecture direction and demonstrate selected useful improvements. They do not establish crash durability, secret-safe arbitrary diagnostics, all-control equivalence, bounded disk use, robust query cancellation, safe command cancellation, source-provenance completeness, or release readiness. Those limits belong beside the result, not hidden in an appendix.
