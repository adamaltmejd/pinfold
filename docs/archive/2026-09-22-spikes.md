# Spikes and investigations, 2026-09-22 to 2026-09-23

Historical record of the evidence behind pinfold's design. The current spec is
`docs/ARCHITECTURE.md` and wins where they differ. Decisions and their reasons are in
`2026-09-23-decisions.md`; this file keeps methods, versions and numbers.

Conventions: sections run in the order the work ran; times are UTC (local dates are the
same). "Observed" means seen in tool output. "Docs" means read from documentation, issue
trackers or source, not tested. "Inferred" is reasoning. The spike scripts lived in a
session scratch directory that is not kept; commands that matter are quoted here.

  1.4.1, builder `container-builder-shim` 0.13.1, vminit 0.35.0. Host git 2.55.0, bun

## 2026-09-22 — Protecting .git with mounts

- **Question.** Can mount options stop the box planting code that host git later runs?
- **Setup.** 19:09–19:13. Scratch repo with one commit, mounted at its own path. Payloads
  were `touch pwned-<name>` markers.
- **Method.** The box writes a hook, `core.fsmonitor` or `.git/commondir`; then host
  `git status` / `git checkout`. Repeated for each mount layout below.
- **Result.** Observed.

| Layout | Outcome |
|---|---|
| Plain `-v repo:repo` | Hook ran on host `checkout`; fsmonitor ran on `status`. |
| commondir, host only (git 2.55.0) | To a dir holding only `config`: repo not recognised. To a valid copy of `.git` with a poisoned config, absolute or relative (`../.evilgit`): fsmonitor ran. |
| Box writes `commondir` → `../.evilgit` | Host ran it. |
| `--read-only-path` on `.git/hooks` and `.git/config` | Enforced. Hook write: `Read-only file system`. `git config`: `could not write config file .git/config: Device or resource busy`. `git commit` works. |
| Rename bypass of the above | `mv .git/config`, `mv .git/hooks`: `Device or resource busy`. `mv .git .git2` succeeds; a poisoned copy put back at `.git` ran on the host. |
| Nested `--mount type=bind,…/.git/hooks,readonly` | Works. |
| Single-file `--mount` | `Error: path … is not a directory`. |
| `.git` as its own mount, hooks read-only | `mv .git`: EBUSY. Config writable; `commondir` creatable. |
| That plus `--read-only-path .git/config` | Config, hooks and parent rename all blocked. `commondir` → valid poisoned dir in the worktree still ran on the host. `git commit` works. |

- Docs: `man git` SECURITY (2.55.0): running git in a `.git` from an untrusted source is
  unsafe. Not tested: `filter.*` with `.gitattributes`, `core.sshCommand`, aliases.
- **Consequence.** No layout that lets the box run git closes `commondir`. Led to the
  per-run git dir and bundle handoff.

## 2026-09-22 — Built-in egress proxy (TypeScript)

- **Question.** Can a small per-box proxy inside the tool replace squid?
- **Setup.** 19:09–19:20. `proxy.ts`, 181 lines, under host bun 1.4.2 (node:net,
  node:dns). Boxes on two new `--internal` /24 networks with `--no-dns --cap-drop ALL`.
  Clients got `HTTPS_PROXY`, `HTTP_PROXY`, `ALL_PROXY=http://box:$TOKEN@<gateway>:<port>`
  and `NO_PROXY=localhost,127.0.0.1`.
- **Spike proxy rules** (the Rust version keeps these; the socket design dropped the
  token and the source check):
  - Listens on 0.0.0.0; only box-subnet sources; exactly one `Proxy-Authorization: Basic`
    equal to a per-box token, else 407 with `Proxy-Authenticate`.
  - CONNECT only to 443, plain HTTP only to 80, only to allowlisted names (exact, or
    `.suffix` for a name and its subdomains). Hostname regex, so no IP literals.
  - Resolves once; refuses if any address is in 0/8, 10/8, 100.64/10, 127/8, 169.254/16,
    172.16/12, 192.0.0/24, 192.168/16, 198.18/15, 224/3, `::/127`, `fc00::/7`,
    `fe80::/10`, `ff00::/8`, `64:ff9b::/96`, `2002::/16`; dials the checked address.
  - Request line `METHOD target HTTP/1.x`; header names are tokens; no CR, LF or NUL; no
    space before the colon; head at most 16 KiB; 15 s header timeout.
  - Plain HTTP: absolute `http://` form, no userinfo, no Transfer-Encoding, at most one
    Content-Length; forwards exactly that many body bytes, one request per connection,
    hop-by-hop headers dropped, `Host` rewritten. Routes: name → host-local `host:port`.
  - One JSON line per decision.
- **Result.** Observed.

| Check | Result |
|---|---|
| `curl https://api.github.com/zen` / `https://example.com/` | 200 / 403 on CONNECT (see it with `-w '%{http_connect}'`) |
| No token, wrong token, two auth headers | 407 |
| `curl --noproxy '*' https://1.1.1.1` | timed out after 5 s (silent drop) |
| Port 8443 or 22 on an allowed name | 403 |
| `git ls-remote https://github.com/git/git HEAD` | OK; git sends CONNECT without credentials, gets 407, retries |
| bun `fetch`, python `urllib`, `uv pip install six`, `bun add is-number` | all worked |
| `GH_TOKEN=dummy gh api /zen` | 401 from GitHub, so it went through |
| node | not in the image; not tested |
| Route `http://yard.internal/` | 200 from a 127.0.0.1 host service; Host rewritten; `Proxy-Authorization` not forwarded |
| CONNECT to the route (`curl -p`) | 200; the tunnel carried two requests with arbitrary Host headers |
| Via proxy to 127.0.0.1, localhost, gateway, `127.0.0.1.nip.io`, `localtest.me` | 403 |
| Box A's token on proxy B, and the reverse | 407 |
| Spawn to listening / in-process `startProxy()` | median 10.1 ms / under 0.1 ms |

- **Smuggling probes** (raw sockets from the box). A request pipelined after a GET, or
  inside a `Content-Length: 0` POST, never reached the upstream. 400: CL with TE, two CLs,
  bare LF, obs-fold, space before colon, `http://yard.internal@example.com/`, `https://`
  as a plain request, non-proxy form, `CONNECT [::1]:443`. 403: `CONNECT 127.0.0.1:443`,
  `CONNECT 2130706433:443`, `CONNECT evilgithub.com:443`, `CONNECT __proto__:80`.
- **Holes in the internal-network boundary** (squid has them too). Observed:
  - `100.100.100.100` (Tailscale MagicDNS) answered DNS from the box despite `--no-dns`.
  - Host services on 0.0.0.0 or `::` answered 200 via the gateway, the LAN address, the
    Tailscale address, IPv6 link-local and the network's ULA; several desktop-app
    listeners were exposed. 127.0.0.1 services were not reachable.
  - Box to box on one network: 200; across networks: timeout. `network create` 0.06 s,
    `delete` 0.08 s.
  - CDN fronting: CONNECT to an allowed name with
    `--connect-to example.com:443:registry.npmjs.org:443` returned "Example Domain"
    (Cloudflare); `www.python.org` via pypi.org worked (Fastly). Host-header fronting: SNI
    `registry.npmjs.org` + `Host: example.com` got a Cloudflare 403; SNI `pypi.org` +
    `Host: www.python.org` got 200.
  - The proxy sees the box's own address (no NAT). Binding the gateway IP fails with
    `EADDRNOTAVAIL` until a box has created the bridge.
- Not tested: a TLS server-name check (proposed only), a live DNS-rebinding service,
  fake-IP DNS proxies vs the 198.18/15 block (inferred). Found in review: no connection
  cap or tunnel idle timeout; an upstream socket leaks if the client leaves during DNS
  lookup; a lowercase `basic` scheme got 407.
- **Consequence.** Per-box in-process proxy adopted; the holes led to the socket design.

## 2026-09-22 — Route lockdown on an internal network

- **Setup.** 20:34–20:39. Own `--internal` network; box user 501:20; host listeners on
  0.0.0.0 (v4 and v6); a Python DNS query script.
- **Method.** Baseline probes. Then PID 1 as root with `--cap-drop ALL --cap-add
  CAP_NET_ADMIN --cap-add CAP_SETUID --cap-add CAP_SETGID --cap-add CAP_SETPCAP`: delete
  default routes, flush IPv6, then `setpriv --reuid … --regid … --clear-groups
  --inh-caps=-all --bounding-set=-all --no-new-privs sleep infinity`. Probes via
  `container exec --user 501:20`.
- **Result.** Observed.

| Probe | Baseline | After lockdown |
|---|---|---|
| Routes | v4 default via gateway; v6 SLAAC ULA and on-link /64, no v6 default | on-link subnet only |
| DNS to 100.100.100.100 | answered | Network is unreachable |
| Host listener via gateway | 200 | 200 |
| Via the LAN address, the Tailscale address, host ULA on the bridge | 200 | unreachable |
| Other host IPv6, other network's gateway, 1.1.1.1, LAN router | unreachable | unreachable |
| Proxy to an allowed host | 200 | 200 |

- `/proc/sys` is read-only, so `disable_ipv6` fails; flushing v6 addresses and routes
  worked. Minimum caps: NET_ADMIN, SETUID, SETGID (SETPCAP only for `--bounding-set`).
  The exec'd user there had CapBnd `0x11c0` and `ip route add` gave `Operation not
  permitted`, but a setuid-root copy of python run by 501 got CapEff `0x11c0` and
  re-added the default route. Not tested: whether a router advertisement restores IPv6.
- **Consequence.** Works but needs capabilities and leaves 0.0.0.0 host listeners on the
  gateway reachable. Kept only as the fallback.

## 2026-09-22 — Socket transport over --ssh

- **Setup.** 20:37–20:41. Python echo and sink servers on host unix sockets in `/tmp`.
- **Method.**
  ```
  container run --rm --network none --entrypoint /bin/sh agentbox:local -c 'ip -brief addr; ip route'
  SSH_AUTH_SOCK=/tmp/pf-spike-echo.sock container run --rm --network none --ssh --user 0:0 …
  ```
- **Result.** Observed.
  - `--network none`: only `lo 127.0.0.1/8 ::1/128`, no routes.
  - The host socket appears at `/var/host-services/ssh-auth.sock` (the guest's
    `SSH_AUTH_SOCK`), root:root, listed in `mount` as a tmpfs entry.
  - Guest mode was `s---------` on the first try, when the host socket did not exist yet
    (its server's bind had failed with `AF_UNIX path too long`, the macOS sun_path
    limit). The box user got `PermissionError: [Errno 13]` on that node. The guest mode
    with a live host socket (0755 on the host) was not listed before the chmod, so 000
    in that case is unverified here; an upstream apple/container issue shows
    `s---------` for a live SSH agent socket.
  - As root: connect plus echo 1.5 ms; 200 KB echoed intact. After root `chmod 666`,
    uid 501 (via `setpriv`) round-tripped data.
  - One 210 MB stream in 0.43 s: 484 MB/s. 32 parallel 20 MB streams: 671 MB in 0.53 s,
    all complete.
  - apple/container#2247 pattern (parallel clients hang on live connections): 3 runs ×
    30 rounds × 32 clients × 20 exchanges (5 ms apart, 3 s timeout) = 57,600
    exchanges, no hangs; `exec` responsive after. The report involves a real SSH agent.
- Docs: `--publish-socket` goes container to host only. #2247 open; #580 (`--ssh` for
  non-root) and #1750 closed.
- **Consequence.** `--network none` plus the forwarded socket replaced per-box networks,
  the proxy token and route lockdown.

## 2026-09-22 — Capability bounding set under --cap-drop ALL

- **Setup.** 20:39–20:44. Box `--user 0:0 --workdir / --cap-drop ALL --read-only
  --network none --ssh`; PID 1 chmods the socket to 666, then
  `setpriv --no-new-privs sleep infinity`.
- **Result.** Observed.

| Check | Result |
|---|---|
| `exec --user 501:20` cap sets | CapInh/Prm/Eff/Bnd/Amb all `0`; NoNewPrivs `0`; Seccomp `0` |
| PID 1 | uid 0, CapPrm/Eff/Bnd `0`, NoNewPrivs `1` |
| `kill(1, 0/15/9)`, `ptrace(ATTACH, 1)` | EPERM |
| `/proc/1/environ`, `/proc/1/mem`, `/proc/1/root/` | EACCES |
| `su -c id root` | `Authentication failure` |
| File capabilities | none in 10,404 files |
| `unshare -Ur` | allowed, CapEff `000001ffffffffff` inside; `chmod 000` on the socket from there: EPERM |
| vsock CID 1 and 2, ports 22/1024/1025/2222 | ECONNRESET |
| Mounts | rootfs `ro`; `/dev/shm` `noexec,nosuid`; virtiofs mounts not `nosuid` |
| Box with `--user 501:20` | exec caps 0; PID 1 cannot chmod the root-owned socket |
| `exec` without `--user`, root PID 1 | uid 0 with the container's cap set |
| Capless root, `WORKDIR` 0700 owned by another user | cannot start the process |

- Docs (source): exec'd processes get the container's `--cap-add`/`--cap-drop` set and
  are started by the VM agent, not forked from PID 1, so PID 1's no_new_privs does not
  reach them. No no_new_privs flag in `run`, `create` or `exec`; the containerization
  library supports it, the CLI does not.
- **Consequence.** `--cap-drop ALL` with no adds is the control; setuid stripped at build.
