# v0.5.1

Disk management now shows readable sizes and recorded origin paths. Empty
scratch runs clean up their home and work disks after a second, read-only
inspection confirms no work remains. Work or uncertainty preserves the disks.

Fix an Apple container 1.6.1 terminal-input flag leak that could interfere
with the shell after Pi exits. Pinfold restores the caller's input flags;
it does not reset the terminal or alter keyboard-protocol modes.

Document reusable host Codex login across independent Pi homes. Shared,
automatically refreshed Anthropic OAuth remains separate work in #260.

## Caller changes

- **Hard break:** `pinfold disk list`, `rm` and successful `export` now
  print human-readable output by default. Scripts must add a trailing
  `--json` to retain their previous structured records and exact byte counts.
- `pinfold clean`, `doctor` and disk inventory use readable size units.
  Human disk inventory shows repository checkout paths and the starting
  folders of new scratch disks. These are origins, not live folder mounts;
  older scratch and caller disks may have no recorded origin.
- New `pinfold disk rm --all` attempts every managed disk in the current
  state root's snapshot. Attached disks are preserved. Other removals
  continue after a failure; any failure makes the command exit nonzero.
- A successful scratch Pi run with confirmed empty work now removes
  **both disks**, including home-only sessions, settings and guest logins.
  Runs with work, incomplete inspection or failed teardown retain disks.
  Empty cleanup can start one transient read-only inspector after shutdown.
- On Apple, failure to restore terminal input flags now fails an otherwise
  successful interactive command. Existing command failures are preserved.

Host-held login routes, resource limits, proxy rules and the CI budget are
unchanged. No OAuth callback forwarding or shared guest auth store was added.
