# v0.2.6 cleanup completion and release validation protocol

2026-10-16. This records the completed cleanup and fixes the release
validation protocol before the final source is tested. Earlier evidence is
identified by its actual source. The release remains held until every final
gate and independent evidence review pass. Final outcomes belong to
[PR #99](https://github.com/adamaltmejd/pinfold/pull/99) and
[issue #92](https://github.com/adamaltmejd/pinfold/issues/92), with immutable
run links and source identities. This dated record is not rewritten.

trace tables, README and architecture. All 37 guarantee rows map to tests
or standalone gates. No executable production statement, safety assertion,
control or feature was removed. The initial account is in
[the October 15 audit](2026-10-15-v0.2.6-code-cleanup.md).

three obsolete G36 bootstrap push-trigger lines, and six duplicate prototype

and all checks remain. G19 now accurately describes its existing Pi-only

completion latency and deadline classification. It became deferred #97.
The Pi mount-order comment was retained because it explains a security
footgun. Existing #94's four failure-only checks in three G12 blocks remain

runtime, proxy, image and trust guards were retained. The skill's obsolete

## Pins and updater failure

The first real updater aborted before writing because stable Rust 1.99.1's
official shared Yard image lacked Linux amd64. Docker Hub and the registry
index agreed. Independently reviewed #98 validates platform-list structure,
defers only the paired Rust/Yard move when an architecture is absent, and
continues other eligible updates. HTTP, parse, malformed-schema and digest
failures still abort before the final write loop. The spec changed in the
same commit, and Ruff passed. No substitute image namespace was used.

The first successful refresh retained Rust/Yard 1.99.0. Both official image
architectures became available later on October 15. The final real refresh
selected Rust/Yard 1.99.1 and Codex 0.163.0. One asset-download timeout before
that successful refresh is retained; it made no file changes. Other release
updates are Pi 1.3.0, Claude 2.1.301, Ponytail 5.1.0, TruffleHog 3.99.2 and
the prototype's transitive @smithy/core 3.35.2. Publisher bytes and digests
were verified. Direct prototype dependencies and Action commit pins did
not change. The workspace version is 0.2.6.

The inherited Bun 1.4.3 pin was published October 10, less than seven days
before the audit. It is byte-identical to v0.2.5 and its publisher digests
match. It was not moved or rehashed here. This is not a claim that every
inherited pin satisfies today's age cutoff. The current contract forbids
moving a pin down or rehashing it at the same version.

Rust 1.99.1 fixes an x64 foreign-ABI boolean-return miscompilation. Earlier
inspection of the actual 1.99.0 x64 artifact found Pinfold's inspected exit
conversions inlined as integer masks, not affected call boundaries. That
was not exhaustive dependency proof. The final release uses the fixed
compiler and requires fresh exact-commit gates.

## Timing investigation

One instrumented diagnostic passed in 269.977934244 seconds:
[38807710931](https://github.com/adamaltmejd/pinfold/actions/runs/38807710931).
During G9's 34.374-second downgraded shared tail, the host averaged only
0.795 CPU cores. Later profile and private-binary builds overlapped under
CPU pressure. This located a mechanism on that host, not every historical
source of variation.

A module-regrouping-only A/B/B/A comparison was rejected:
[38810777730](https://github.com/adamaltmejd/pinfold/actions/runs/38810777730).

All safety outcomes, G35 and cleanup checks passed. Neither B result
established a useful gain over final A; B2 also avoided E2E recompilation.
The first scheduling model omitted the standard lock's conservative writer
flag. Rust 1.99.0's exact futex implementation and intact traces showed
fresh readers blocked through G9's shared tail even without another queued
writer. A corrected model reproduced the observed schedule and screened
about 23 seconds of possible overlap. Model output is not measured gain.

The combined source moves the complete G8/G15/G37 bodies to runtime.rs and

The grouping-only Mac export passed 33 tests in 216.66 complete seconds,
plus G35/typecheck. The combined Tokio export passed 33 tests in 247.72
libtest seconds; complete elapsed time was 1,759.69 seconds across confirmed
maintenance sleeps. Neither Mac preflight is comparative timing evidence
or a substitute for final-source validation.

## Fixed final validation and publication

Freeze shipping source, pins, version and this record before validation.
Temporary drivers check out that exact candidate and do not ship. Ordinary
acceptance uses scripts/e2e-budget.py around the complete Cargo command,
with no instrumentation, sampler, capture override or prebuild outside its
timer. All real compilation remains included.

Three sequential rounds each create fresh normal x64, cold-musl x64 and
normal ARM jobs. Keep all nine outcomes. Every complete command must pass
and finish below 300 seconds; each normal x64 command must also be at most
270 seconds. Only cold-musl jobs remove target/x86_64-unknown-linux-musl
after ordinary cache restoration and lint. No retries or replacement
samples. Native overlay, default workers, private compilation and controls
remain. Source/cache/runtime/cleanup evidence lives outside target. Every
completed suite with clean runtime state also runs G35 and frozen prototype
install/typecheck, including a budget-only failure.

The identical commit also requires the full Mac suite with live login,
Mac G35/typecheck, G34 on all three hosts, G36 on both Linux architectures,
and all three release builds. Runtime gates are sequential within a host.
Independent reviewers judge outcomes, provenance and failures. This is
finite engineering acceptance with explicit headroom, not a universal
bound on hosted machines.

After approval, promote the tested descendant to main by non-force
fast-forward, rejecting concurrent divergence. Wait for ordinary main CI,
then push an annotated v0.2.6 tag at the identical tested commit. Insert no
new source commit solely to record completed results. Release notes carry
Caller changes: none to Pinfold's box spec, JSON lines, exit codes or flags.
They link Pi's custom Kimi /v1 change and identify updated bundled tools.
After publication, verify the actual downloaded assets against SHA256SUMS
and GitHub digests, inspect target formats and execute the downloaded Mac
binary. Prepublication builds alone do not prove delivered asset integrity.
