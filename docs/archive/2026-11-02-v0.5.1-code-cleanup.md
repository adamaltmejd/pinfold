## Coverage and dispositions

Independent whole-file audits covered every product Rust module, all e2e
files and fixtures, profiles, scripts, workflows, bootstrap/kernel producers,
manifests, README and built help. The required test sweep found no assertion
block to delete. Dependencies match the spec; dead-code checking found none.

Landed by module:

- 307d8e5: remove unused Asset serialization; PinAsset still defines reports.
- 57245df: reuse bulk disk removal in test teardown, deleting its duplicate
  enumeration, JSON parsing and per-disk subprocess loop. Assertions unchanged.
- fe7d181: remove repeated scratch/auth configuration prose and stale
  unconditional scratch-retention wording from README.
- 25ef997: remove repeated cache wording and state the existing terminal
  restoration-failure exit behavior explicitly in the spec.

Rejected:

- Replacing the local-config presence check with Layer::read alone would
  lose refusal after an observed local file disappears. Re-admit only with
  that trust-boundary behavior preserved.
- Reusing core::hex from builder init breaks the standalone init crate on
  Linux x64. A new shared module solely for nine lines is not justified.
- Podman migration instructions still tell upgrading callers what to do.
  Re-admit their removal when that migration guidance is no longer useful.
- No unmeasured optimization or optional control-code rewrite was included.

Local ticket 1, deferred: consolidate disk_export's manual bounded copy
loop with the installed Tokio copy capability. Remove the duplicate loop
only after separate review preserves exact length/EOF bounds, active-file
ownership, flush/sync, cancellation and closed-writer cleanup. No change to
this containment path is part of v0.5.1.
