# End-to-end tests for guarantees 5, 8, 11 and 45

2026-11-20. Second step of #297: one test per row on the existing harness.
All four pass against main's binary (e5158a5) on macOS. Linux was not
run: the dev VM did not answer.

Row 5 is not fully proven. Its "Shown by" says the image has no setuid or
setgid file, but box work, as the host uid, cannot read the whole image:
`find / -xdev -type f -perm /6000` in the box exits 1 with five
`Permission denied` lines (below). The test asserts the weaker "no setuid
or setgid file box work can reach". The removed suite ran the same `find`
with stderr dropped. Whether to reword the row, or to inspect the image
from outside the box, is the operator's spec decision; the row is
unchanged.

No product bug was found. One behaviour of `box prune` is left to triage
(Findings).

Setup: macOS 27.2, Apple `container` 1.7.1, via
`CARGO_TARGET_AARCH64_APPLE_DARWIN_RUNNER="sh $PWD/scripts/run-mac-e2e.sh"
cargo test -p e2e --locked --test e2e`. The existing `profile-default`
image was used; none was built or removed.

## Harness additions

`crates/e2e/src/lib.rs`:

- `TestEnv::new` runs `pinfold disk list --json` under a process-wide lock,
  `hold_maintenance()`. A state root's first working command runs the
  daily maintenance pass, which prunes every dead box on the host. Spending
  it at creation, under the lock, means no test's pass lands while another
  test holds the lock between an owner's SIGKILL and its own `box prune`.
  Rows 8 and 11 hold it for that window. The user's own daily pass can
  still land in it.
- `TestEnv` drop lists the disks in its state root (`disk list --json`)
  and removes each with `disk rm NAME`, after the test's boxes. A failure
  is printed and keeps the roots.
- `TestEnv::start(spec)`: the box, or the line `up` printed instead of
  `ready` after `up` exits 1. `up` is `start` that must come ready.
- `BoxUp::kill_owner`: SIGKILL of `box up`, reaped (exit 137). It returns
  a `Leftover`, whose drop runs `box down NAME` only while `box list`
  still shows its generation; `box down` removes only an orphan.
  `Leftover::listed` wraps a box found by `box list`.
- A second state root is a second `TestEnv`.
- `TestEnv::listed(run_id)`, `TestEnv::root`, `BoxUp::ready`,
  `json_lines`, and `wait_until` (the bounded child wait `run` already
  had, now shared).

## Tests

**`nothing_can_gain_privileges` (5).** Box on the `default` image. The
exec'd perl forks, the child forks, the grandchild execs a fresh perl.
That process reads `/proc/self/status`: all four Uid fields are the host
uid (from host `id -u`); CapInh, CapPrm, CapEff, CapBnd and CapAmb are 0;
NoNewPrivs is 1. `unshare(CLONE_NEWUSER)` by syscall number (97 on arm64,
272 on x64) returns errno 28 (ENOSPC). Control: in the same process
`system('true')` returns 0 and `unshare(0)` succeeds. A write to
`/pinfold-e2e-probe` fails with errno 30 (EROFS); `/tmp` takes it. A
second box's `boot_id` differs. On Linux (not run): PID 1's CapPrm, CapEff
and CapBnd are `0000000000200000`; the exec'd command's parent has PPid 1,
the host uid and every set 0; neither box's `boot_id` is the host's.

`find / -xdev -type f -perm /6000` in the box printed nothing on stdout
and exited 1 with:

```
find: '/lost+found': Permission denied
find: '/etc/ssl/private': Permission denied
find: '/root': Permission denied
find: '/var/cache/apt/archives/partial': Permission denied
find: '/var/cache/ldconfig': Permission denied
```

The setuid scan therefore walks the root file system in perl without following links
or leaving the device. As the host uid it cannot list five root-owned
directories: `/etc/ssl/private`, `/lost+found`, `/root`,
`/var/cache/apt/archives/partial`, `/var/cache/ldconfig`. The test asserts
no setuid or setgid file elsewhere, and that `chdir` into each unlistable
directory fails with EACCES, so nothing below one can be executed. Control:
the same scan of `/tmp` finds a mode-4755 file the box makes there. So the
test shows "no setuid or setgid file box work can reach", not literally
none in the image: box work cannot read the whole image.

Sabotage: drop `--cap-drop ALL` from `container run` (runtime/apple.rs).
Failed on the grandchild's CapBnd `00000000a80425fb`, not 0.

**`losing_the_owner_fails_closed` (8).** A box allowing `api.github.com`.
A script prints a marker, then `curl -w %{http_connect}` to
`https://api.github.com/`: marker and `200`, exit 0. SIGKILL of `box up`.
On Apple the same script in the orphan prints the marker and `000`, curl
exit 56 ("Proxy CONNECT aborted": the guest relay accepts, nothing is
behind it). The test accepts 7 or 56, never 28. From a second state root,
`box list --label dev.pinfold.generation=RUN` shows the box with the killed
pid and `owner_alive: false`; `box prune` there prints
`{"event":"pruned","box":NAME,"owner":PID}`; `container list --all` no
longer lists it; a new `up` with the name comes ready. Then a share project
(`git init`, `VISUAL=true pinfold config edit`): `pinfold -- sh -c 'echo
started; exec sleep 600'` prints `started`; `box list --label
dev.pinfold.project=ID` (the id from `config --json`) gives the detached
owner's pid; after `kill -KILL` the client exits 125. Its stderr named
`session-protocol` and `pinfold box inspect RUN`.

Sabotage: replace `clean::prune_boxes` in cli.rs's `prune` with nothing.
Failed on the other root's prune printing no line; the `Leftover` drop
removed the orphan by name.

**`disks_persist_and_attach_exclusively` (11).** Two writable `up`s,
started on two threads, name one new disk: one comes ready, the other is
refused `disk-in-use`. The writer writes a marker and `sync`s. Under the
maintenance lock: SIGKILL of the writer's owner; a read-only `up` is
refused `disk-in-use`; `box prune` prints the writer's `pruned` line; the
same read-only `up` is refused `disk-unclean`. A writable run reads the
marker (control); `disk rm NAME --json` meanwhile exits 1 with
`{"event":"refused","disk":NAME,"reason":"disk-in-use",…}`. After that run
ends with `down`, the read-only run comes ready and reads the marker;
`disk rm` then exits 0 with `existed: true`.

Sabotage: skip the `disk-unclean` refusal in core/disk.rs's `claim`.
Failed: the read-only `up` after the prune came ready.

**`disk_export_writes_only_a_new_destination` (45).** A box writes, on a
writable disk, `link` to an absolute host file the test made, `tool` (mode
755) and `plain` (mode 600), then ends with `down`. Export to an existing
empty directory exits nonzero (observed 1, which the spec does not name)
and prints no `exported` line; the directory keeps its
inode and stays empty; nothing new appears beside it. Control: export to a
new directory exits 0 with `{"event":"exported",…}`. It is mode 700 and
holds exactly `link`, `plain`, `tool`: `link` is a symlink to the host
path, `tool` is 755, `plain` 644 (the spec's normalization). The host
file's content, inode, mtime and mode are unchanged.

Sabotage: delete the `fstatat` existing-destination check in
core/disk_export.rs and publish with plain `renameat`, not
`renameatx_np(RENAME_EXCL)`. Failed: the export into the existing empty
directory exited 0. A first attempt that only skipped the `fstatat`
branch still failed the export, with a stale EAGAIN from
`last_os_error`; the test passed under that partial sabotage, so the
recorded sabotage removes the whole check.

Every sabotage was reverted; `git status crates/pinfold` was clean.

## Findings

- Row 8, second state root, to triage: `box prune` is a working command,
  so in a root that has not yet spent its daily pass, maintenance prunes
  the dead box first and `prune` then prints nothing. The spec says prune
  prints one line per removed box. Read from source (main.rs's maintenance
  dispatch, clean.rs `maintain_due`); not reproduced, because the manual
  probe was refused (Shared machine). The test's second root spends its
  pass at creation, before the kill.
- Row 45: the spec names no reason token or exit code for an existing
  destination. The CLI exits 1 and its stderr starts `destination-exists:`;
  the test asserts neither, only a nonzero exit, no `exported` line and the
  unchanged directory.
- Row 5: "the image has no setuid or setgid file" is observable from box
  work only where box work can read (above).

No "Shown by" wording was changed.

## Shared machine

Before the first run and after the last, `container list --all`,
`container volume list` and `container image list` were identical: the
user's project box and its two volumes were untouched, and its owner was
alive throughout. One manual `box prune` probe was refused by the
session's permission classifier and not run; the probe's own orphan was
removed by name (`container kill`, `stop`, `rm`), and its stale ownership
record by an `up`/`down` of the same name. Prune only removes boxes whose
name lock is free (`clean::prune_boxes` and `prune_leftover_states` take
`try_name_lock`, `remove_orphan` rechecks the generation); a live owner
holds that lock, and prune never removes a disk. The suite's temp roots,
its cache directory and the probes' roots were removed.
