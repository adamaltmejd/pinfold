# v0.7.0 release audit, 2026-11-23

The code-cleanup pass with test-audit's sweep, then the spec pass, before
0.7.0. Fourteen read-only readers covered every source module, the
harness, the test files in two groups, the spec with `profile/`, and the
README with the help text. Nothing was edited in that phase. The findings
landed in #448 (spec, README, help), #449 (code) and #450 (the cuts Adam
approved, and one bug fix), each with one Codex reviewer.

## Why the landed net is under a third of the possible net

The readers called many things duplicates that were not. The builders
were told to skip anything not provably identical, and the reviewer
then found more.

- The docs builder cut a spec sentence only where it could name another
  place stating the same rule. The spec lost 11 lines, not 79.
- The code builder skipped eleven approved findings on close reading: a
  changed syscall, a changed JSON key, a changed error text, a changed
  check order.
- The review of #449 found six more that differed from main, and they
  were restored: the proxy's worker reap loop, both init lookups on the
  Git crossing, the remote helper's `dup`, a label order in the image
  job, `Client::kill` in the harness, and all four test blocks the sweep
  had called twins. Each test block was the only proof of its case. The
  pass removed no test assertion.

## Adam's list

Six findings touched the spec or a second layer of checking. Adam took
all of them on 2026-11-23, against the operator's advice on the last
three.

| Finding | Answer | Outcome |
| --- | --- | --- |
| Rex answer from an owner off macOS | Take | Removed with its spec sentence. |
| `clean` repeats the daily pass's steps | Take | Withdrawn in review, below. |
| The login helper's own kill and reap | Take | The helper runs in its own process group through `GroupChild`. |
| The guest re-validates the BOOT request | Take | Four checks removed, each enforced by the host before it sends. One has no host check and stays. |
| The guest re-validates the builder's devices | Take | Removed. The host writes that request from fixed values. No spec sentence stated it. |
| curl's `--max-time` and `--max-filesize` | Take | Removed. pinfold's deadline and byte limit bound every transfer. curl keeps its connect timeout and speed limit. |

The merge of `clean`'s steps with the daily pass was built and then
withdrawn. On main the two run the same steps in different orders, and
`clean` measures after a due daily pass but before its own steps. Two
review rounds each found cases that depend on one of those orders, in
opposite directions. No single order keeps both. `clean` and the daily
pass are unchanged.

The review of #448 found a bug, fixed in #450: the daily pass ran before
`clean --dry-run`, so a dry run could delete expired run records and
unpinned artifacts. A dry run now runs no automatic pass, and row 15's
test covers it.
